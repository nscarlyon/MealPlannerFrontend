# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Personal meal planner frontend: Angular 22 (standalone components, signals), Angular Material, Vitest. It talks to a separate backend API at `http://localhost:5137`.

## Commands

The Angular CLI requires Node v22.22.3+, v24.15+ or v26+. If `ng` refuses to start, switch Node versions (e.g. `nvm use 24.19.0`).

```bash
npm start                  # ng serve → http://localhost:4200
npm run build              # production build to dist/
npm run lint               # angular-eslint over src/**/*.ts and src/**/*.html
npm test -- --watch=false  # run all Vitest unit tests once (ng test watches by default)
npx ng test --watch=false --include='src/app/features/meal-list/**/*.spec.ts'   # run a subset
npm run generate-api       # regenerate API client with orval (backend must be running)
```

The test build type-checks **every** spec file, even with `--include`. A compile error in any spec blocks all tests from running.

Tests use Vitest globals (`vi.fn()`, `describe`, `it`). Specs mock generated services with `{ provide: MealsService, useValue: { getApiMeals: vi.fn().mockReturnValue(of(...)) } }`.

Formatting: Prettier (`printWidth: 100`, single quotes, Angular parser for `.html`).

## API layer (generated — do not edit by hand)

`src/app/api/` is generated by orval (`orval.config.ts`) from the backend's OpenAPI spec at `http://localhost:5137/openapi/v1.json`:
- `api/generated/<tag>/<tag>.service.ts`: one `providedIn: 'root'` Angular service per API tag (`MealsService`, `WeeklyMealPlanService`, `MonthlyMealPlanService`, …), with methods named like `getApiMeals`, `getApiMealsId`. They return Observables.
- `api/models/`: request/response interfaces and TS `enum`s (`MealType`, `CuisineType`, `DayOfWeek`, …).

When the backend contract changes, regenerate rather than editing these files. Then fix usages, including spec test data, since stale fields in mock objects break the test build.

## App architecture

- `app.routes.ts` wires feature components directly (no lazy loading). The router uses `withComponentInputBinding()`, so route params and resolver data arrive as component inputs (e.g. `meals/:id` resolves `meal` via `resolvers/MealsResolver.ts`).
- `features/`: one folder per page (meal list, create/edit meal, view meal, weekly and monthly meal plans, shopping list). `CreateMeal` serves both `meals/add` and `edit-meal/:id`.
- `shared/`: reusable UI (`confirm-dialog`, `in-viewport` directive, `meals-search-bar` with its `filter-meals-dialog`) and `shared/states/` for shared state services.
- `guards/unsaved-changes.guard.ts`: a `canDeactivate` guard for components implementing `HasUnsavedChanges`. It shows `ConfirmDialog` before leaving.

### Data-fetching pattern

Pages load data with Angular's `resource()`. The `params` function reads signals and the `loader` calls a generated service via `firstValueFrom(...)`. Changing any signal read in `params` refetches automatically. `linkedSignal` is used for derived state that must also be locally writable (e.g. keeping the previous results while reloading, editable copies of loaded plan items, resetting `pageIndex` to 0 when search or filters change).

### Shared component state

Sibling or child components share state through a plain `@Injectable()` service (no `providedIn`) listed in the parent component's `providers`. The state then belongs to that page instance and resets when you leave it. Example: `MealList` provides `shared/states/meal-search-state.ts`. `MealsSearchBar` writes the search text and filters to it, and `MealList`'s `mealsResource` reads from it. Any component using `<app-meals-search-bar>` must have `MealSearchState` provided by an ancestor (or in its spec's `providers`).

### Forms

`CreateMeal` uses Reactive Forms (`NonNullableFormBuilder`). A form model lives in `features/create-meal/meal-form-model.ts`.
